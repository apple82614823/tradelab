# Security and sensitive information

Only the latest public revision is a maintenance target. This project does not
offer an SLA, a bug bounty, or certification for live trading.

Do not include credentials, production databases, personal account records,
server addresses, or executable access material in public issues or PRs.
Use synthetic examples whenever possible.

If GitHub's **Report a vulnerability** feature is enabled for this repository,
use that private reporting channel. If it is unavailable, open an issue asking
for a private contact route without disclosing the details. A maintainer will
arrange an appropriate channel before requesting sensitive diagnostic material.

If you accidentally publish a credential, revoke or rotate it with its provider;
removing the visible text alone does not invalidate a downloaded copy.

Never grant withdrawal permissions for a research checkout. The recommended
evaluation path is offline tests without any exchange credentials. Check the
actual provider/account rules yourself before configuring any live access.
